# 成电寻路

电子科技大学软件设计课程的校园室内路径规划 Demo。直接双击 `index.html` 即可运行；运行资源均在本地，无需安装依赖、联网、后端或构建工具。

## 新对话接续摘要

- **项目现状**：纯 HTML、CSS、原生 JavaScript 和 SVG 的单页原型。首页选起终点并预览位置，路线页同时显示左侧文字指引与右侧地图，详情页展示同样粒度的分层指引。地图与路径由共享拓扑数据生成，路径使用 Dijkstra 算法计算。
- **最新交互**：左侧路线卡片下半部分是可滚动的步骤列表，**每经过一层只显示一条**；悬停或键盘聚焦临时预览该层，点击固定该层并高亮对应路线。路线页默认打开“室外 · 总览”，在同一张全图上用不同颜色叠加各楼层路线；切换楼层后只显示该层路线。路线页不会自动放大到某个分区，仍可手动缩放。
- **C区现场图更新**：C区五层按现场导视图分别配置房号、相对位置和教室长度比例，包含2F的C215A/B/C和4F的A/B后缀门牌。斜边内侧为25%休息区、50%楼梯、25%休息区；1F两条斜边外侧整段为出入口，与2F的C211～C213、C217～C219立面对齐。照片无北向标记，精确方位、长度与跨区连接点仍待实测。
- **跨区连接**：室外道路及所有一楼入口在同一地面路网内互通；2F 有 ABC 三向中央露天连廊；3F 有 A—C、B—C 两条侧连廊。门牌递增箭头不代表单行。两端都在地面/1F 时，规划优先使用地面路网。
- **视觉与适配**：本地引入 Auroraqua-UI 玻璃材质和 asciify-engine 字符背景；蓝青色动态高斯光场、深浅主题、桌面/横屏/手机布局，以及减少动态效果和减少透明度适配均已接入。
- **关键文件**：`js/data.js` 是几何和路网数据源，`js/dijkstra.js` 负责寻路，`js/map.js` 绘制 SVG 地图与分层路线，`js/app.js` 负责页面和交互；`index.html` 与 `css/` 负责结构和样式。`maps/` 是独立 SVG 导出，当前运行时地图由共享几何直接生成。
- **验收边界**：既有拓扑和路线曾进行脚本核对，记录见文末；最新的分层步骤与多楼层总览尚未由用户完成浏览器验收。下一轮应以用户实际验收反馈为准，不把静态检查写成视觉或交互验收通过。
- **协作约束**：分析或修改代码时，先用中文说明正在做什么，不要默默运行命令。用户自行验收网页；不要操作其浏览器或桌面界面。

## 使用

- 首页预览起点与终点：可点室外入口选起点，点建筑查看楼层，点教室选终点。
- 起终点支持5个室外入口、13个建筑入口和245个按当前数据配置的房间（A/B共104间、C共141间）；输入门牌可快速查找，交换按钮可调换起终点。
- 地图支持室外、1F～5F、全图/分区视图、缩放和放大后拖动。5F只有C区。
- 开始规划后，左侧按经过的楼层各显示一条指引，右侧同时展示路线；悬停或聚焦会临时预览该层，点击后固定高亮。展开页也使用相同的分层粒度。
- 路线页的“室外 · 总览”以不同颜色显示所有经过的楼层；切换至单层时只看该楼层路线段。
- 路线页固定使用全图视角，只切换楼层，不随起终点或步骤自动放大到A/B/C局部；仍可用地图右下角按钮手动缩放。
- 右上角切换深浅主题；首次打开跟随系统，手动偏好保存在本机。无法访问本机存储时不影响使用。
- 手机竖屏为单列，横屏和桌面为地图与操作面板并列。

## 界面

直接使用 Auroraqua-UI 的现成玻璃面板、按钮和输入框CSS：低透明度底色、模糊与色彩饱和、多层阴影和边缘高光。页面采用分离悬浮面板；地图与正文保留清晰对比。上游材质原始声明保存在 `vendor/auroraqua/materials.css`，本地加载，无需联网、React或Tailwind。

背景使用 asciify-engine 3.0.1 的 `wave` 渲染器：字符场由三层正弦波和FBM噪声持续流动，鼠标附近产生平滑追随、涡旋挤压、密度与字符变化。其下是三组克莱因蓝/青色高斯光场，使用不同周期漂移与呼吸，形成缓慢变化的透光底板。页面隐藏时暂停ASCII渲染；系统开启“减少动态效果”后移除ASCII动画并冻结光场。

按钮直接使用上游0.2秒缓动、悬停1.02倍放大、按下0.98倍缩小及0.6秒扫光。选点面板使用上游悬停阴影消退效果，标签选中样式从上游TabButton组件转译，保留0.7秒扫光并将粉色色相适配为成电蓝。已有页面进入、路线绘制和统计递增仍保留。系统开启“减少动态效果”后停用动画。

手机先显示总览图，再显示起终点选择；横屏改为并排。入口增加透明点击区域，地图重绘会保留键盘焦点，视野外的位置不参与 Tab 顺序。支持系统减少动态效果、减少透明度；不支持背景模糊的浏览器使用实色面板。

## 已确认的拓扑规则

- A/B各4层，每层01～13。C区按现场导视图：1F为C101～C120（20间）；2F为C201～C231，其中C215分A/B/C（33间）；3F为C301～C336（36间）；4F至C423，其中C401、C402、C403、C404、C406各分A/B（28间）；5F为C501～C524（24间）。
- A的01在南侧偏西，B的01在西侧偏北，均沿顺时针环廊递增。
- C区五层分别配置房号与布局。教室沿同一排连续分隔：2F长短教室约1.5:1，4F的C405约为A/B半间教室的2倍，5F的C502/C504各为对面两间教室的长度；1F的C109与C110～C112整排对齐。斜边两间或三间教室共用整段立面，1F同一立面为整段出入口。2F的C230/C231之间保留中央入口空档，3F侧排保留辅助用房空间。
- C区两处斜边内侧分别沿边划分为25%休息区、50%楼梯、25%休息区，共四处侧翼休息区；楼梯路网接点位于梯段中央。卫生间、电梯、物管、开水间、研讨室等设施目前仅供辨认，不作为独立目的地。
- A/B各4座楼梯，C有5座；C区电梯已标在图面，尚未接入无障碍路线或跨层寻路。
- **地面层互通**：外围道路、C与AB之间的横向道路、AB之间的中央通道及南侧道路，连接全部建筑入口。A/B各四角入口，C北侧两个、南侧三个入口，可在地面进入任意区的一楼，无需为了跨区先上楼。
- 2F中央露天连廊三向连接ABC；3F两侧连廊分别连接A—C和B—C。高层连廊与地面步道分别建模，4F/5F没有跨区连廊。
- 1F地图同时展示地面步道和一楼室内路线，室内外边界不计入换层次数。路线页的室外总览在地面底图上按颜色叠加所有经过楼层的路线；要查看高层连廊与教室的底图细节，需切换至所属楼层。
- 环廊、连廊和楼梯均为双向边。编号箭头不表示单行限制。

## 仍属示意的数据

建筑比例、每侧门牌的精确间距、教室尺寸、建筑入口的精确坐标和步行距离均待实测；各入口的相对方位按用户紫色箭头标注。A/B暂按外侧教室布置。C区现场导视图没有北向标记；依据现场补充说明，将照片布局在现有总图中逆时针旋转90°，使斜角边远离A/B、宽直边朝向露天连廊。跨区连廊与地面入口的精确落点仍需现场核对。早期原型中的微波实验室因位置未核实，不再作为可规划地点。

两端均在室外或1F时，默认**地面优先**：在地面路网内求最短路径，避免为了少走几米先上楼再下楼。涉及高层时使用完整路网。界面明确显示这一偏好，并将相邻的室外与1F行程合并为“地面 / 1F”。独立的 `dijkstra()` 仍保留任意节点的全图最短路能力。

路程按估算边权计算，步行时间按80米/分钟。楼梯每相邻层暂记18米等效步行距离；连续经过同一座楼梯的多层合并为一次“换层过程”。界面按经过的楼层汇总路线和估算距离，总时长向上取整到分钟；这些数值不是实测距离或用时。

## 文件与地图替换

- `js/data.js`：建筑边界、环廊、门牌编号位置、楼梯、室外节点及连廊连接。C区使用逐层房号及相对布局数据，门牌和走廊的节点由几何数据统一生成。
- `js/dijkstra.js`：独立最短路径算法，支持任意现有节点；非法节点或不可达返回空路径。
- `js/map.js`：从同一套几何生成SVG底图和动态路线。
- `scripts/export-maps.js`：用 Node.js 从共享几何重导出室外总图和五张楼层SVG；网页运行本身不需要Node.js。
- `js/app.js`：页面、选点、主题、地图缩放和路线详情。
- `css/style.css`：界面与地图共用的颜色变量、毛玻璃层次、深色模式和响应式布局。
- `vendor/auroraqua/`：固定版本的上游CSS、提取后实际加载的材质、组件源码、MPL-2.0许可证和来源说明。
- `vendor/asciify-engine/`：固定提交的上游Wave/FBM源码、离线浏览器适配、MIT许可证和来源说明。
- `js/background.js`：ASCII背景参数与动画生命周期；页面隐藏或系统减少动态效果时停止渲染。
- `css/glass.css`：Auroraqua与现有界面的布局、颜色及辅助功能适配；标签样式为上游组件的CSS转译。
- `maps/`：室外与5张楼层图的独立SVG导出。运行时直接用共享几何绘图，不请求这些导出文件，避免本地文件读取限制，也便于主题联动。

本轮C区依据项目上一级目录的 `C 1F.jpg`～`C 5F.jpg` 更新共享几何，并同步重导出 `maps/outdoor.svg` 和 `maps/floor1.svg`～`maps/floor5.svg`。运行 `node scripts/export-maps.js` 可再次导出。相对长度为导视图估读值，并非实测尺寸。后续若接入测绘级平面图，可继续校准共享几何；若改用 `floorPlanImages` 外部图像，还需同步校准节点坐标、配色和可点击区域。不要只替换导出的SVG而保留旧节点坐标。

## 验证记录与待验收项

旧版模型曾通过240组路线的独立最短距离对照、路径边权和步骤总距离检查；那次记录不适用于本轮C区重绘。本轮已核对C区五层房间数量为20/33/36/28/24，全部节点ID无重复、边的端点存在，抽查了各层及分号房间的可达性，五张楼层SVG通过XML解析。完整浏览器视觉与交互仍由用户验收。

2026-09-27补充核对：C区141个房间均可从入口1寻路到达；五层教室、斜边楼梯与休息区的凸多边形相交检查无重叠；两处斜边整段立面均在建筑轮廓内。两个斜边入口分别到C101/C109/C113/C120/A101/B101的12组路线均可仅用地面与1F节点连通。室外与五张楼层SVG通过XML解析，并完成独立静态渲染检查；浏览器交互仍待用户验收。

地面互通修正另检查：移除所有高层节点后，5个室外入口到13个建筑入口的65组连通关系、到55间一楼普通教室的275组连通关系均成立；检查一楼跨区路线无楼梯、室内外路段在1F视图连续绘制，进出建筑不计上下楼。

以上是此前拓扑和路线的脚本验证记录，不等于最新界面的浏览器验收。SVG底图先前采用独立渲染检查，不能替代完整浏览器验收；Liquid Glass 样式完成了资源引用、变量和响应式规则的静态检查。分层步骤的悬停、聚焦、点击联动，多楼层总览的路线颜色，以及实际玻璃效果和触屏表现，均以用户后续浏览器验收为准。后续扩展的1,224组路线核对因临时验证器异常中止，未计入通过项目；网页本身不需要该验证器或Python。
